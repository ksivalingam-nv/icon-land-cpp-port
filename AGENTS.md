## What this is

A deliberately reduced copy of ICON (`icon/icon-mpim`): everything not needed to run the Fortran land model ICON-Land (JSBACH) *standalone* in its `jsbach_lite` usecase, plus the C++/Kokkos subproject `ragnarok/` (without its microphysics package), has been removed. It is a scaffold for porting ICON-Land to C++, not a development line: it cannot be merged back into or synced with `icon-mpim`. No atmosphere, ocean, waves, coupling or NWP/AES physics can be built from it.

## What is left

- `src/`, `support/` -- exactly the dependency closure of the standalone land executable (226 files): infrastructure in `shared`, `parallel_infrastructure`, `io`, `namelists`, `configure_model`, `grid`, `shr_horizontal`, `drivers`, plus single modules elsewhere that the infrastructure or the land adapter still `USE` (e.g. `atm_phy_aes/mo_aes_thermo.f90`, `atm_phy_schemes/mo_thdyn_functions.f90`). `src/shared/mo_util_jsbach.f90` is the host adapter ICON-Land talks to.
- `externals/jsbach` -- ICON-Land reduced to the `jsbach_lite` usecase; see its own `AGENTS.md`. It is an ordinary directory of this repository, not a submodule: it was vendored from the jsbach repository at commit `03f30edbb` (`icon-land-2026.04-25-g03f30edbb`, i.e. release `icon-land-2026.04` plus 25 commits) and then reduced. Keep all land code, Fortran and C++, inside this directory so it can be split out again (`git subtree split --prefix=externals/jsbach`).
- Submodules: `externals/cdi`, `externals/mtime`, `externals/fortran-support`, `externals/iconmath`, `externals/memman`, `externals/kokkos` and `utils/mkexp`.
- `externals/memman` (MemMan, release 2.2.0) is built unconditionally and backs every variable created through `add_var` (`src/shared/mo_var_list.f90`), so all ICON-Land variables registered with `Add_var` are MemMan-allocated. A var list can opt out with `vlr_add(..., lmemman=.FALSE.)`. This was taken from the `icon-mpim` branch `feature-enable-memman-unconditionally` (not merged upstream at the time); a C++ compiler is therefore a hard requirement of the build.
- `ragnarok/` -- `common/`, `support/` (kernels, memory, timer, testing, icon_bridge) and `aes_thermodynamics/`. The ICON bridge is cut down to what the standalone land model can serve: patch/grid access, halo sync, timers, logging and `finish`. Its Fortran side is `src/shared/mo_ragnarok_support.f90`; ragnarok is initialised and finalised from the land driver `externals/jsbach/src/drivers/mo_jsbach_model.f90`. There is no interpolation state, no non-hydrostatic metrics, no AES config mirror and no testbed.
- `test/unit-tests/` -- Fortran unit tests of kept infrastructure (`make check-icon`).
- `run/` -- only the mkexp setup for the land standalone experiment on Levante (`run/mkexp/`), the test config `run/checksuite.icon-land/test_jsb_standalone.config` and the example `run/examples/JSB-standalone-R2B4.config`.
- `config/dkrz/levante.*` -- the only build wrappers.
- `.gitlab-ci.yml`, `.gitlab/ci/` -- reduced to the ragnarok unit jobs and the land `jsb-standalone` build/run/analyze jobs. Reduced structurally only: never run on GitLab; the reference checksums in `.gitlab/ci/data/system-checksum-table.yml` predate the reduction and the switch to `jsbach_lite`.

`configure.ac` still carries all options of full ICON, but only the defaults work: atmo, les, upatmo, ocean, coupling, aes, nwp and rte-rrtmgp default to off, jsbach and ragnarok to on. Enabling a removed component fails at configure or compile time. `#ifdef` branches for removed components are still in the kept sources. `configure` is generated: after changing `configure.ac` run `autoreconf -fvi` (Autoconf 2.69, as on Levante).

## Build

```bash
mkdir -p build/x && cd build/x
../../config/dkrz/levante.intel --enable-openmp   # or another config/dkrz/levante.* wrapper
make -j24
make -j16 check-icon                              # Fortran unit tests
```

The NAG wrapper passes `--disable-ragnarok`: ragnarok's Fortran interface (`ragnarok/support/icon_bridge/mo_ragnarok_f2c.f90`) does not compile with NAG.

Only files in the dependency closure of `src/drivers/icon.f90` are compiled. `make srclist` writes that closure to `srclist` without compiling.

Ragnarok alone, with its GoogleTest unit tests:

```bash
cmake -C ragnarok/cmake/caches/levante_cpu_gcc.cmake -S ragnarok -B <build-dir> \
      -DFETCHCONTENT_SOURCE_DIR_KOKKOS=$PWD/externals/kokkos
cmake --build <build-dir> --parallel 16
OMP_NUM_THREADS=4 OMP_PROC_BIND=false ctest --test-dir <build-dir>
```

Limit the OpenMP threads as shown; on a login node `ctest -j` otherwise fails with `libgomp: Thread creation failed`.


Pass criteria: the job ends `COMPLETED`, the log in `experiments/<id>/log/` has 12 `: ok` lines from the built-in diff test, and every output and restart file under `/scratch/.../experiments/<id>/work/run_19790101T000000-19790101T023000/` is identical to a run of the tree before your change (`cdo -s diffn <before> <after>` prints nothing).

## Removing more code

1. Produce reference output from the unchanged tree in the same configuration.
2. Remove, rebuild, rerun, compare with `cdo diffn`. A removal must not change results.
3. To find unused sources, compare `git ls-files src support` with `make srclist`. Two caveats: the unit tests need `test/unit-tests/common/mo_test_common.f90` and their own closure, and includes written with angle brackets are invisible to the dependency generator (`src/include/add_var_acc_macro.inc` is needed although `srclist` does not list it).

## Conventions

- License header: every source/config file starts with the standard ICON copyright block (`Copyright (C) 2004-2026, DWD, MPI-M, DKRZ, KIT, ETH, MeteoSwiss`, `SPDX-License-Identifier: <license>`). Match neighbouring files. Files in `externals/jsbach` use the ICON-Land header instead.
- Fortran modules are prefixed `mo_*`.
- Don't hand-edit generated Autotools output (`configure`).
