Scope, tracing method, and limitations
  1. Static source analysis of tracked Fortran declarations, CALL statements, known function references, USE imports, renames and selected type-bound bindings. No compiler, application build, or runtime tracing.
  2. The application view is a source-verified overview of the retained standalone land path. Phase headings are editorial groups, not additional subroutines. Task ordering comes directly from jsbach_init.
  3. The routine explorer includes raw source branches. Preprocessor guards are recorded, not evaluated. Dormant branches for removed ICON components can therefore appear there.
  4. Generic calls show possible overloads. Dynamic task targets are resolved from constructor types and Integrate/Aggregate bindings; runtime process/tile activation still controls execution.
  5. Other polymorphic calls, procedure-pointer calls, macro-generated calls and unresolved dependencies are incomplete. Unresolved nodes are labeled; uninitialized external submodules are not scanned.
  6. Function references are lexical candidates, not compiler-proven calls. Edges marked inferred use a unique routine-name match rather than complete Fortran name resolution.
  7. The C++ bridge is traced manually for initialization, finalization and host callbacks. Other C++ implementation call graphs are not comprehensively indexed.
  8. Repeated callees unfold as separate tree occurrences. Recursion is stopped at a cycle marker. Static source order is not a measured execution sequence or frequency.
